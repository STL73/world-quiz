# Phase 1: Schema and Data Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this
> plan task-by-task, inline, with Slav in the loop. Steps use checkbox (`- [ ]`) syntax for
> tracking. Subagent-driven execution is not used: every file is explained to Slav before the next
> one is written.

**Goal:** the PHP version's 46 questions, 16 countries, 3 users and their scores live in the Neon
`dev` branch, every question's photo loads from Cloudinary, and tests prove the schema's rules.

**Architecture:** a Drizzle schema of four tables (`users`, `scores`, `countries`, `questions`),
turned into SQL by drizzle-kit and applied to the Neon `dev` and `test` branches. A one-off script,
`backend/scripts/importFromMysql.js`, reads XAMPP's MySQL `wq_db`, uploads the photos to Cloudinary
first, then writes the rows to Neon and checks every count and every photo. Its row conversions
live in `scripts/transform.js`, apart from the database and network code, so they can be tested on
their own.

**Tech stack:** Drizzle ORM 0.45 + drizzle-kit 0.31, `@neondatabase/serverless`, Cloudinary 2,
mysql2 3 (development only, for the import), bcryptjs 3, Vitest + Supertest. Versions match
`D:\MY PROJECTS\manchester-event` and npm on 2026-11-16.

**Spec:** `docs/superpowers/specs/2026-11-15-react-rebuild-design.md`

## Decisions taken while planning (2026-11-16)

| Decision | Choice | Why |
| --- | --- | --- |
| Tables in phase 1 | `users`, `scores`, `countries`, `questions` | The four the import fills. `sessions` and `attempts` arrive in phase 2 with the code that uses them (Slav) |
| Regions | Not in phase 1. `countries` has an id and a name only | Slav wants a world map where a chosen country fills with its flag's colours. That needs its own design discussion, which will decide region, continent and country codes together (Slav) |
| Key names | `user_id`, `country_id`, `question_id` | `manchester-event`'s convention; the spec's `id` was shorthand |
| Import script location | `backend/scripts/`, not `database/` | It needs the backend's packages and its `db` client, which Node can't find from `database/` |
| Data source | The live MySQL `wq_db` | Only it has the users. Checked 2026-11-16: 46 questions (ids 1 to 46, each with exactly one correct answer), 3 users (all `$2y$` bcrypt), 3 scores |
| Ids | New ids from Neon, not the MySQL ones | Nothing outside a table points at a question id (the PHP app keeps the saved question in the session), and the user ids are mapped while scores are copied |
| Photo names in Cloudinary | `world-quiz/<NODE_ENV>/questions/<country>-q<n>`, e.g. `brazil-q1`, with `overwrite: true` | Re-running the import replaces each photo instead of adding copies. The name comes from the country column, not the folder (`Brasil`) |

The spec is updated with these in Task 1.

`$2y$10$7svSkmGvq1JpHko0uHBRA.97sAzZmvHkageUaiAV0.VXUASH4C.CW`. Any output of that shape works;
the hash differs on every run because the salt is random.

```js
import { sql } from 'drizzle-orm';
import { pgTable, integer, varchar, smallint, index, check } from 'drizzle-orm/pg-core';

// A country the landmarks belong to
export const countries = pgTable('countries', {
    countryId: integer('country_id').primaryKey().generatedAlwaysAsIdentity(),
    name: varchar('name', { length: 100 }).notNull().unique(),
});

// One landmark photo and its three possible answers
export const questions = pgTable('questions', {
    questionId: integer('question_id').primaryKey().generatedAlwaysAsIdentity(),
    // A country can't be deleted while it still has questions
    countryId: integer('country_id').notNull().references(() => countries.countryId, { onDelete: 'restrict' }),
    imageUrl: varchar('image_url', { length: 500 }).notNull(),
    // Cloudinary's name for the photo, so a replaced one can be deleted
    cloudinaryId: varchar('cloudinary_id', { length: 255 }).notNull(),
    question: varchar('question', { length: 150 }).notNull(),
    hint: varchar('hint', { length: 150 }).notNull(),
    answer1: varchar('answer1', { length: 100 }).notNull(),
    answer2: varchar('answer2', { length: 100 }).notNull(),
    answer3: varchar('answer3', { length: 100 }).notNull(),
    // One number instead of three true/false flags, so exactly one answer is always right
    correctAnswer: smallint('correct_answer').notNull(),
}, (table) => [
    check('questions_correct_answer_range', sql`${table.correctAnswer} BETWEEN 1 AND 3`),
    // Postgres doesn't index a foreign key by itself; finding a country's questions needs one
    index('questions_country_id_idx').on(table.countryId),
]);
```

Explain: `pgTable` (a table described in JavaScript), the camelCase key and snake_case column name
on every line, `generatedAlwaysAsIdentity` (Postgres numbers the rows itself), `references` and
`onDelete`, why `correct_answer` replaces `is_correct1..3` (three flags can be all false or two true;
one number can't), the CHECK, and why the foreign key gets an index. Walk through Brazil's first
question as a row.

- [ ] **Step 4: Write `backend/src/db/schema/users.js`**

```js
import { sql } from 'drizzle-orm';
import { pgTable, pgEnum, integer, varchar, timestamp, check } from 'drizzle-orm/pg-core';

import { questions } from './quiz.js';

export const roleEnum = pgEnum('role', ['user', 'admin']);

// A player or an admin. People log in by email
export const users = pgTable('users', {
    userId: integer('user_id').primaryKey().generatedAlwaysAsIdentity(),
    name: varchar('name', { length: 100 }).notNull(),
    // Stored lowercase: the app lowercases it on sign-up and login
    email: varchar('email', { length: 255 }).notNull().unique(),
    passwordHash: varchar('password_hash', { length: 255 }).notNull(),
    role: roleEnum('role').notNull().default('user'),
    // timestamptz, so the stored time doesn't depend on the server's time zone
    createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
});

// A player's tokens and where they stopped. The level is worked out from the tokens, never stored
export const scores = pgTable('scores', {
    userId: integer('user_id').primaryKey().references(() => users.userId, { onDelete: 'cascade' }),
    starTokens: integer('star_tokens').notNull().default(10),
    // NULL = start from the first question. Deleting the question only clears it
    savedQuestionId: integer('saved_question_id').references(() => questions.questionId, { onDelete: 'set null' }),
}, (table) => [
    check('scores_star_tokens_not_negative', sql`${table.starTokens} >= 0`),
]);
```

Explain: `pgEnum` (a list of allowed values, like MySQL's `enum('admin','user')`), why `scores`
uses `user_id` as its primary key (one score per user, enforced), `cascade` versus `set null`,
why the level isn't a column (it can never disagree with the tokens), and the MySQL
`score.level` column that this drops.

```js
// Turns rows read from the PHP version's MySQL database into rows for Neon

// The number of the right answer, 1 to 3. MySQL kept three flags, so this checks exactly one is set
export function correctAnswerOf(row) {
    const flags = [row.is_correct1, row.is_correct2, row.is_correct3].map(Number);
    const count = flags.filter((flag) => flag === 1).length;
    if (count !== 1) {
        throw new Error(`Question ${row.id} has ${count} correct answers`);
    }
    return flags.indexOf(1) + 1;
}

// Cloudinary's name for a question's photo, e.g. 'brazil-q1': the country, then the q-number in the file name
export function imagePublicId(country, imgPath) {
    const match = /\/(q\d+)-[^/]*$/.exec(imgPath);
    if (!match) {
        throw new Error(`No question number in ${imgPath}`);
    }
    const countrySlug = country.trim().toLowerCase().replace(/\s+/g, '-');
    return `${countrySlug}-${match[1]}`;
}

// A Neon question row, given the country's new id and the photo's Cloudinary address and name
export function toQuestion(row, countryId, photo) {
    return {
        countryId,
        imageUrl: photo.url,
        cloudinaryId: photo.publicId,
        question: row.question,
        hint: row.hint,
        answer1: row.answer1,
        answer2: row.answer2,
        answer3: row.answer3,
        correctAnswer: correctAnswerOf(row),
    };
}

// A Neon user row. The PHP hash is kept as it is: bcryptjs reads $2y$ hashes
export function toUser(row) {
    return {
        name: row.name,
        email: row.email.trim().toLowerCase(),
        passwordHash: row.password,
        role: row.user_type === 'admin' ? 'admin' : 'user',
    };
}
```

in milliseconds with made-up rows), the regular expression in `imagePublicId` piece by piece, and
why a bad row stops the import (better to stop than copy a broken question).

- [ ] **Step 1: Write `backend/scripts/importFromMysql.js`**

```js
import path from 'node:path';
import mysql from 'mysql2/promise';
import { sql } from 'drizzle-orm';

import { db } from '../src/db/index.js';
import { users, scores, countries, questions } from '../src/db/schema/index.js';
import { cloudinary, questionImageFolder, questionImageUrl } from '../src/config/cloudinary.js';
import { correctAnswerOf, imagePublicId, toQuestion, toUser } from './transform.js';

// One-off copy of the PHP version's data into Neon. XAMPP's MySQL must be running.
// `npm run db:import` refuses a database that already has data; `npm run db:import -- --reset` empties it first

// `||`, not `??`: an empty MYSQL_URL= line in .env counts as not set
const MYSQL_URL = process.env.MYSQL_URL || 'mysql://root@localhost:3306/wq_db';
// The PHP app's folder: every img_path in MySQL starts from here
const PHP_APP_DIR = path.resolve(import.meta.dirname, '../../src');
const RESET = process.argv.includes('--reset');
// A player with no score row in MySQL starts like a new player
const NEW_PLAYER_TOKENS = 10;

async function readMysql() {
    const connection = await mysql.createConnection(MYSQL_URL);
    try {
        const [userRows] = await connection.query('SELECT id, name, email, password, user_type FROM users ORDER BY id');
        const [scoreRows] = await connection.query('SELECT id, star_tokens FROM score');
        // The PHP version's `countries` table holds the questions, one row each
        const [questionRows] = await connection.query('SELECT * FROM countries ORDER BY id');
        return { userRows, scoreRows, questionRows };
    } finally {
        await connection.end();
    }
}

async function prepareNeon() {
    const hasUsers = (await db.$count(users)) > 0;
    const hasQuestions = (await db.$count(questions)) > 0;
    if ((hasUsers || hasQuestions) && !RESET) {
        throw new Error('Neon already has data. Run `npm run db:import -- --reset` to empty it first');
    }
    if (RESET) {
        // RESTART IDENTITY starts the numbering from 1 again
        await db.execute(sql`TRUNCATE TABLE scores, users, questions, countries RESTART IDENTITY`);
        console.log('Emptied users, scores, countries and questions');
    }
}

async function uploadPhoto(row) {
    const result = await cloudinary.uploader.upload(path.join(PHP_APP_DIR, row.img_path), {
        // The folder is part of the name, so the same name in another folder is a different photo
        public_id: `${questionImageFolder}/${imagePublicId(row.country, row.img_path)}`,
        // Running the import again replaces each photo instead of adding a copy
        overwrite: true,
        resource_type: 'image',
        transformation: [{ width: 1600, crop: 'limit' }],
    });
    return { url: questionImageUrl(result), publicId: result.public_id };
}

async function check({ userRows, questionRows }, countryCount) {
    const counts = [
        ['users', userRows.length, await db.$count(users)],
        ['scores', userRows.length, await db.$count(scores)],
        ['countries', countryCount, await db.$count(countries)],
        ['questions', questionRows.length, await db.$count(questions)],
    ];
    let passed = true;
    for (const [table, expected, found] of counts) {
        console.log(`${table}: expected ${expected}, found ${found}`);
        if (expected !== found) passed = false;
    }

    // Uploaded isn't enough: each photo must load from the address saved in Neon
    const saved = await db.select({ questionId: questions.questionId, imageUrl: questions.imageUrl }).from(questions);
    for (const { questionId, imageUrl } of saved) {
        const response = await fetch(imageUrl, { method: 'HEAD' });
        if (!response.ok) {
            console.log(`Question ${questionId}: photo answered ${response.status}`);
            passed = false;
        }
    }
    console.log(`Photos checked: ${saved.length}`);
    return passed;
}

async function main() {
    console.log(`Neon: ${new URL(process.env.DB_URL).host}`);
    const mysqlData = await readMysql();
    const { userRows, scoreRows, questionRows } = mysqlData;
    console.log(`MySQL: ${userRows.length} users, ${scoreRows.length} scores, ${questionRows.length} questions`);

    // A broken question stops the import here, before anything is uploaded or written
    questionRows.forEach(correctAnswerOf);
    await prepareNeon();

    // Photos first: the slowest step and the likeliest to fail, so Neon is only written once they're all up
    const photos = [];
    for (const row of questionRows) {
        photos.push(await uploadPhoto(row));
        console.log(`Uploaded ${photos.length}/${questionRows.length}: ${photos.at(-1).publicId}`);
    }

    const countryNames = [...new Set(questionRows.map((row) => row.country))];
    const countryRows = await db.insert(countries).values(countryNames.map((name) => ({ name }))).returning();
    const countryIds = new Map(countryRows.map((country) => [country.name, country.countryId]));
    await db.insert(questions).values(questionRows.map((row, i) => toQuestion(row, countryIds.get(row.country), photos[i])));

    // One user at a time, to pair each MySQL id with the id Neon gives the user
    const tokensByMysqlId = new Map(scoreRows.map((row) => [row.id, row.star_tokens]));
    for (const row of userRows) {
        const [user] = await db.insert(users).values(toUser(row)).returning({ userId: users.userId });
        await db.insert(scores).values({ userId: user.userId, starTokens: tokensByMysqlId.get(row.id) ?? NEW_PLAYER_TOKENS });
    }

    const passed = await check(mysqlData, countryNames.length);
    console.log(passed ? 'Import complete: every count matches and every photo loads' : 'Import FAILED the checks above');
    process.exitCode = passed ? 0 : 1;
}

main().catch((error) => {
    console.error(`Import stopped: ${error.message}`);
    process.exitCode = 1;
});
```

Explain, in the order the script runs: reading MySQL with a connection that is always closed
(`try/finally`), the safety check before anything is deleted, why photos go first, the `Set` that

````markdown
## Schema conventions (Drizzle)

- Tables: `pgTable('<snake_plural>', ...)`, exported as camelCase (`users`)
- Columns: camelCase JS key, snake_case DB name: `userId: integer('user_id')`
- Primary keys: `integer('<table>_id').primaryKey().generatedAlwaysAsIdentity()`
- Enums: `pgEnum('<snake_name>', [...])`, exported as `<name>Enum`
- Every date column is `timestamp(..., { withTimezone: true })`
- Rules the data must always follow are CHECK and UNIQUE constraints in the schema, so they hold for
  the import and any future script too, not only for the routes
- A new schema file must be exported from `schema/index.js`, or drizzle-kit won't see it

No npm scripts for drizzle-kit; run it with npx from `backend/`:

```bash

npx drizzle-kit migrate                          # apply to the dev branch (DB_URL)
DB_TARGET=test npx drizzle-kit migrate           # apply to the test branch (TEST_DB_URL)
````
